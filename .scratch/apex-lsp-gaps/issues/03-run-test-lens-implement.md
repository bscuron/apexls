## Question

Implement the "Run Test" code lens exactly as settled in [ticket 02](02-run-test-lens-decision.md)'s Answer: the `codeLensProvider` capability declaration, `Backend::code_lens` (and `workspace/executeCommand` handler if that's the mechanism ticket 02 chose) in `lib.rs`, and a new `capabilities.rs` function producing the lenses from already-resolved `@isTest`/`is_testmethod` data. Validate against the real NPSP corpus's own `@isTest` classes and methods (lens appears at every one, none spuriously elsewhere).

## Answer

Shipped exactly as ticket 02 settled it. `apex-binder::dead_code`'s `is_platform_invoked_test_method` was widened from `pub(crate)` to `pub` and re-exported from the crate root; a new sibling `is_test_class` (class-level `@isTest` detection, extending `annotations_of`'s match with a `SymbolKind::Class` arm) sits beside it. `capabilities::run_test_lenses` walks `program.symbols.iter()` for a file, emitting one `CodeLens` per `@isTest` class and per `@isTest`/`@TestSetup`/legacy-`testMethod` method, each `Command`'s `arguments` naming the *top-level* enclosing class (walking `Symbol::container` to the outermost type, so a test method nested in an inner class still names the real compiled `ApexClass`). `Backend::code_lens` and `Backend::execute_command` (`apexls.runTest`) were added to `lib.rs`'s `impl LanguageServer for Backend`, plus `code_lens_provider`/`execute_command_provider` in `initialize`'s capabilities. `execute_command` spawns `sf apex run test --tests <target> --result-format json --json --synchronous` via `tokio::process::Command`, with `current_dir` set to the resolved workspace root (a review finding on the first pass: `sf` resolves both its SFDX project and its default-org config relative to its cwd, which an LSP client's own process cwd is not guaranteed to match) -- never passing `-o`. `summarize_apex_test_output` parses the uniform JSON envelope into a `window/showMessage` summary.

Tests: 4 new `apex-binder` unit tests (`is_test_class` true/false), 4 new `apexls-server` unit tests for `summarize_apex_test_output` (passing/failing/CLI-rejection/unparseable), and a new `tests/code_lens.rs` protocol-level suite (class+method lens placement, legacy `testMethod`, no spurious lens on an ordinary class, and the nested-inner-class top-level-name case) -- 4/4 passing. Validated against the real NPSP corpus via a throwaway sweep (deleted before commit, matching ticket 01's own precedent): zero panics across all 1,066 files; 397 of 399 files with raw `@isTest`/`testMethod` text got a lens, and no file got a lens without such text anywhere in it (no spurious lenses). Full `cargo test -p apex-binder -p apexls-server` and `cargo check --workspace` pass.
